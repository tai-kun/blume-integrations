---
title: ブラウザーの言語でルーティング
description: 言語プレフィックスのない URL を、訪問者のブラウザー言語に合うロケールへ転送します。
---

`routeByBrowserLanguage()` は、`/guide` のような言語プレフィックスのない URL へのアクセスを、訪問者のブラウザー言語に合う `/ja/guide` や `/en/guide` へ転送する Astro 統合です。Blume の i18n と組み合わせて使い、静的ビルドのまま言語別の入口を作れます。

## できること [#what-it-does]

- ローカルストレージの `blume-locale` に保存されたロケールがそのページを配信している場合は、そのロケールへ転送します。Blume の言語スイッチャーで選んだ言語が保存されており、ブラウザーの言語設定より優先されます。
- 保存されたロケールが使えない場合は、ブラウザーの言語設定（`navigator.languages`）を先頭から調べ、一致するロケールへ転送します。`ja-JP` は `ja` に一致します。
- どちらにも一致する言語がない場合は、そのページを配信している範囲で、Blume のフォールバックロケール、`en`、転送先の先頭の順に選びます。
- クエリ文字列と URL フラグメントを引き継ぎます。
- JavaScript を実行しないクライアント向けに、転送先のリンクをページ上に表示します。
- 言語スイッチャーからプレースホルダーロケール `und` を隠します。

## 仕組み [#how-it-works]

Blume の既定ロケールを `und` に設定したうえで、この統合は次の 2 つを追加します。

1. すべての HTML ページの `</head>` 直前に、言語スイッチャーの `und` を隠す CSS を挿入します。
2. `/[...slug]` のキャッチオールルートを追加し、言語プレフィックスのない URL ごとにリダイレクトページをビルド時に生成します。

この統合は Astro や Blume の i18n 設定を変更しません。`i18n.defaultLocale` には `FAKE_DEFAULT_LOCALE.code`（`und`）を自分で設定してください。`und` を既定ロケールにすると、翻訳するロケール（`ja` や `en` など）は言語プレフィックス付きで配信され、コンテンツのルートにページを置かない限り、言語プレフィックスのない URL に実ページは存在しません。この統合は、その空いた URL をリダイレクトの入口として使います。

## セットアップ [#setup]

```package-install
npm i @tai-kun/blume-integrations
```

`blume.config.ts` の `integrations` に統合を追加し、Blume の `i18n.defaultLocale` に `FAKE_DEFAULT_LOCALE.code` を設定したうえで、`i18n.locales` に `FAKE_DEFAULT_LOCALE` を追加します。

```ts blume.config.ts
import {
  FAKE_DEFAULT_LOCALE,
  routeByBrowserLanguage,
} from "@tai-kun/blume-integrations";
import { defineConfig } from "blume";

export default defineConfig({
  integrations: [routeByBrowserLanguage()],

  i18n: {
    defaultLocale: FAKE_DEFAULT_LOCALE.code,
    locales: [
      { code: "ja", label: "日本語" },
      { code: "en", label: "English" },
      FAKE_DEFAULT_LOCALE,
    ],
  },
});
```

`FAKE_DEFAULT_LOCALE` は `{ code: "und", label: "und" }` です。`und` は ISO 639-2 で言語不明を表すコードです。`defaultLocale` にはこの `code` を設定し、`locales` にも追加して、Blume にプレースホルダーロケールを認識させます。`und` 用のページを用意する必要はありません。コンテンツのルートにはページを置かないでください。配置方法は後述します。

:::note
Blume の i18n が設定されていない場合、この統合はリダイレクトページを作成しません。
:::

## コンテンツの配置 [#content-layout]

`und` が既定ロケールなので、Blume は既定ロケールのページをコンテンツのルートに探します。ルートにはページを置かず、すべてのページを `ja/` や `en/` などのロケールのフォルダーに置きます。

```txt
content/
  en/
    index.mdx
    guide.mdx
  ja/
    index.mdx
    guide.mdx
```

この構成では、`/` や `/guide` へのアクセスを、訪問者の言語に応じて `/ja/` や `/en/`、`/ja/guide` や `/en/guide` へ転送します。

コンテンツのルートにページを置くと、Blume はそのページを `und` として言語プレフィックスなしで配信します。その URL には実ページが存在するため、この統合はリダイレクトページを作成しません。

## 動作確認 [#verify]

ビルドしたサイトで、言語プレフィックスのない URL（`/guide` など）を開きます。ブラウザーの言語設定に一致するロケール、または Blume の言語スイッチャーで最後に選んだ言語のページへ転送されれば成功です。言語の選択が保存されていない場合、ブラウザーの言語設定を変えると、選ばれるロケールも変わります。

## 転送先の選び方 [#matching]

リダイレクトページは、その URL を配信しているロケールだけを転送先の候補にします。候補は `i18n.locales` の設定順です。クライアント側では次の順に転送先を決めます。

1. ローカルストレージの `blume-locale` にロケールが保存されており、そのロケールがページを配信している場合は、そのロケールを選びます。Blume の言語スイッチャーで選んだ言語は、このキーに保存されます。
2. 保存されたロケールが使えない場合は、`navigator.languages` を先頭から調べ、ロケールコードと完全に一致するか、ロケールコードの後ろに `-` が続く言語タグを探します。たとえば `ja-JP` は `ja` に一致します。
3. 一致するものがない場合は、Blume の `fallbackLocale` を選びます。ただし、そのページを配信している場合に限ります。
4. `fallbackLocale` が使えない場合は `en` を選びます。ただし、そのページを配信している場合に限ります。
5. どれも使えない場合は、候補の先頭のロケールを選びます。

| ブラウザーの言語 | ページを配信するロケール | 転送先 |
| --- | --- | --- |
| `ja-JP` | `ja`、`en` | `/ja/guide` |
| `en-US` | `ja`、`en` | `/en/guide` |
| `fr-FR` | `ja`、`en` | `fallbackLocale` が `en` なら `/en/guide` |
| `fr-FR` | `ja` のみ | `/ja/guide` |

転送では `window.location.replace()` を使うため、ブラウザーの履歴にはリダイレクトページが残りません。リダイレクトページ自体は言語の選択を保存しません。保存するのは Blume の言語スイッチャーだけです。ストレージが使えない環境では保存されたロケールを読めないため、ブラウザーの言語設定から選びます。

## リダイレクトの対象 [#scope]

次の URL にはリダイレクトページを作成しません。

- サイドバーで非表示にしたページ（`sidebar.hidden: true` または `hidden: true`）
- どのロケールも配信していない URL
- 実際のページがすでに存在する URL（既定ロケールのページなど）

バージョン付きの URL にも対応します。`/v1/guide` は `/ja/v1/guide` へ転送します。デプロイ先のベースパスと Blume の `basePath` も転送先に含まれます。

サイトのルート URL（`/`）は、末尾にスラッシュを付けたロケールのルート（`/ja/`）へ転送します。

## JavaScript を実行しない場合 [#without-javascript]

転送はクライアント側の JavaScript で行います。実行できない場合に備えて、リダイレクトページには転送先の一覧がリンクとして表示されます。AI エージェントやクローラーも、このリンクから各言語のページへ到達できます。

## 言語スイッチャーから und を隠す [#hide-placeholder]

この統合は、全ページの `</head>` 直前に次の CSS を挿入します。

```css
[data-blume-header] [hreflang="und"][lang="und"] {
  display: none;
}
```

これにより、Blume のヘッダーにある言語スイッチャーから `und` の項目が隠れます。CSS はプリレンダー時にも挿入されるため、静的ビルドの HTML に残ります。

ヘッダー以外に独自の言語スイッチャーを置いている場合は、同じ属性を持つ要素に別途スタイルを当ててください。

## API [#api]

| エクスポート | 型 | 説明 |
| --- | --- | --- |
| `routeByBrowserLanguage` | `() => AstroIntegration` | 統合を作成します。 |
| `FAKE_DEFAULT_LOCALE` | `{ code: string; label: string }` | Blume の `defaultLocale` と `locales` に設定するプレースホルダーロケール `und` です。 |

## 注意点 [#caveats]

- Blume の `i18n.defaultLocale` を `und` に設定し、コンテンツのルートにはページを置かないでください。言語プレフィックスのない URL に実ページがある場合、そのページはそのまま配信され、転送されません。
- リダイレクトは JavaScript で行うため、初回表示時に一瞬リダイレクトページが表示されることがあります。
- 生成されるのは静的な HTML です。サーバー側で言語を判定するわけではありません。
- 言語スイッチャーの `und` を隠す CSS は、Blume のヘッダーのマークアップ（`data-blume-header`、`hreflang`、`lang`）に依存します。
